# Auto-set tmux `@theme` on macOS so nvim picks the system light/dark variant

## Context

- nvim (shared config, `lua/plugins/colorscheme.lua` → `tmux_background()`) reads
  `tmux show-options -gv @theme` at startup: exactly `light` → light, else dark.
- On this machine nothing sets `@theme` → nvim is always dark. That is the bug.
- `TODO-mac-theme.md`'s "Decide first" premise is outdated: no
  `zshrc_term_theme`/`zshrc_term_borders` in `~/.zshrc`. Real state: Ghostty
  follows macOS system appearance (`theme = light:Adwaita,dark:Adwaita Dark`
  in `~/.config/ghostty/config`), and the 7s poller (renamed to
  `scripts/theme-poller.sh` by this plan) polls `defaults read -g
  AppleInterfaceStyle` every 7s for pane borders.
- Chosen structure: mirror `main`'s `scripts/theme.sh` (per-machine file), and
  keep a separate watcher script, renamed `theme-poller.sh`. Note: future
  `git merge main` will hit an add/add conflict on `scripts/theme.sh` — accepted
  tradeoff for structural symmetry.

## Changes

### 1. NEW `scripts/theme.sh` (bash, mirrors `origin/main:scripts/theme.sh` shape)

Header comment marks the cross-branch contract — this file exists on both
branches with different code, so every merge of `main` conflicts here and the
resolver needs to know what each side is:

```bash
#!/usr/bin/env bash
set -eu

# ----- macOS variant: Ghostty follows the system appearance, so mode() reads
# AppleInterfaceStyle. main's variant reads Windows Terminal's settings.json
# and also toggles (origin/main:scripts/theme.sh) -----
```

No other comments — names carry the rest.

Single owner of mode detection, `@theme`, and border colors:

- `mode()`: `defaults read -g AppleInterfaceStyle 2>/dev/null | grep -qF Dark`
  → `dark` / `light` (same probe the current poller uses).
- `apply() [mode]`: sets `@theme` AND the global border styles, reusing the
  current mac palette:
  - dark: `pane-border-style "fg=#5e5c64,reverse"`,
    `pane-active-border-style "fg=#57e389,reverse,bold"`
  - light: `fg=#c0bfbc,reverse` / `fg=#2ec27e,reverse,bold`
- `case "${1:-}" in mode|apply) ;; *) usage; esac` — no `toggle` (theme is
  system-driven on macOS, like borders today).
- No tmux-session guard needed: only called from `tmux.conf` and the poller,
  both under a running server.

### 2. RENAME `scripts/border-poller.sh` → `scripts/theme-poller.sh` (git mv)

Loop body becomes one delegation so mid-session appearance flips update
`@theme` too (for nvims opened after the flip). Also rename the pidfile to
`/tmp/tmux-theme-poller.pid`:

```sh
while true; do
  "$HOME/.config/tmux/scripts/theme.sh" apply
  sleep 7
done
```

### 3. EDIT `tmux.conf` — PANE BORDERS, macOS block (lines 232-236)

Keep the existing branch-marker comment convention. The block becomes exactly:

```
# ----- macOS: theme.sh apply() sets @theme + border colors from AppleInterfaceStyle; theme-poller.sh re-applies every 7s for mid-session switches -----
run-shell -b "$HOME/.config/tmux/scripts/theme.sh apply"
run-shell -b "pidfile=/tmp/tmux-theme-poller.pid; [ -f \"\$pidfile\" ] && kill \"\$(cat \"\$pidfile\")\" 2>/dev/null; $HOME/.config/tmux/scripts/theme-poller.sh"
# /----- macOS -----
```

Changes vs today:
- Delete the two hardcoded light `pane-border-style` lines — colors now live
  only in `theme.sh` (single source, like WSL where `apply()` owns them).
- The old poller spawn line is updated in place (new script name + pidfile).
- New `theme.sh apply` line matches `main`'s identical line, so it converges
  at the next merge.
- `pane-border-lines single` stays. Leave the stale `# ----- Linux (main
  branch) -----` block (lines 226-230) untouched — the next merge from
  `main` will flag it.

Its instructions say to delete once done.

## Verification

1. `~/.config/tmux/scripts/theme.sh mode` prints `dark`/`light` matching
   `defaults read -g AppleInterfaceStyle`.
2. `tmux source ~/.config/tmux/tmux.conf`, then
   `tmux show-options -gv @theme` prints the same value; pane borders show the
   matching color.
3. Flip macOS appearance (System Settings → Appearance), wait ≤7s,
   `tmux show-options -gv @theme` flipped. Flip back.
4. Start nvim: `:echo &background` matches the mode;
   `:lua print(vim.g.onedark_config.style)` → `light` in light mode,
   `darker` in dark mode.
5. `tmux kill-server`, start a new session → step 2 holds at startup.
